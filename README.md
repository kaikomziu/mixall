# MixAll（旧ネットリファイ）

認証、掲示板Uch、チャット「ぽけっと」、複合SNS Ghost、疑似メールMail、貸し出しサイトなどをまとめた統合Webプラットフォームです。
もとは Netlify Functions + Netlify Blobs で作られていましたが、**GitHub Pages + Supabase** で動くように移行しました。

## 現在の構成（GitHub Pages + Supabase）

| 部分 | 場所 |
|---|---|
| 画面（静的HTML/JS） | `public/` → `scripts/build-pages.mjs` で `build/` に変換 → GitHub Pages（`/mixall/` 配下） |
| API | `netlify/functions/*.js`（旧コードをほぼそのまま利用）を `server/entry.js` で束ね、Supabase Edge Function **mixall-api** として動かす |
| データ | Supabase Postgres `public.mixall_kv`（旧Blobs互換KV。`netlify/lib/store.js`） |
| チャット本文 | **端末（IndexedDB）に保存**。サーバーにはメッセージIDなどのスタブだけを残す（下記） |
| 定期実行 | pg_cron（`supabase/cron.sql`） |
| 設定値 | `mixall_kv` の store=`mixall-config` key=`env`（Edge Functionのシークレットが優先） |

### 端末保存チャット（Pocket / Ghostチャット / Mail / Ghostライブ）
- 保存時に `server/chat-vault.js` が本文（text・添付・件名など）を抜き出し、宛先アカウントの各端末あてに `public.mixall_chat_inbox` へ入れる。保存されるのは `vault:true` のスタブだけ。
- 端末は API 応答に同梱される `__vault` を `public/js/chat-vault.js` で IndexedDB に保存し、次の要求の `x-mixall-ack` で受領を伝える。受領した行はサーバーから削除。未受信の行は30日（旧サイトからの移行分は365日）で期限切れ。
- 検索・TXT書き出し・地雷フィルターの原文表示は端末側で処理。通報時だけ、通報者の端末から該当本文を証拠として送る。運営のチャット監査では本文は見えない。
- Ghostライブのチャットは配信中だけサーバーにあり、終了してアーカイブになるときに本文を消す。
- 投票（集計が必要）と添付ファイルの実体はサーバーに残る。新しい端末では、使い始める前のメッセージ本文は表示されない。

### Googleドライブ連携（任意）
- 連携した人だけ、端末のチャット本文を Googleドライブのアプリ専用フォルダ（appDataFolder、スコープ `drive.appdata`）にも保存する。`public/js/google-drive-sync.js`。アカウント設定画面に連携カードが出る。
- ブラウザとGoogleの間だけで通信し、Googleのトークンは MixAll のサーバーへ送らない。ファイルは MixAll アカウントごとに `mixall-chat-<ハッシュ>.json`。
- 有効化: Google Cloud で OAuth クライアントID（ウェブアプリ、承認済みJavaScript生成元 `https://kaikomziu.github.io`）を作り、GitHub リポジトリの Actions 変数 `MIXALL_GOOGLE_CLIENT_ID` に登録して再デプロイ。

## 主な機能

### 認証・セキュリティ

- `[ユーザー名]@bix.3erver` 形式の疑似メールアカウント認証
- scryptによるパスワードハッシュ保存。パスワードの平文・ハッシュ値は画面へ返しません
- トップ画面のログイン中デバイス一覧
- 端末ごとの最終利用時刻確認と個別セッション失効
- 本人確認後に運営が一時パスワードを発行する管理者リセット
- 運営アカウント `bix.admin@bix.3erver` はサーバー側で全体権限を判定

### 運営・公認アカウント

- 公認アカウントは通常の名前と異なる色・公認バッジで表示
- 運営アカウントは所属グループやスレッドの主に関係なく、許可された管理操作を利用可能
- `/admin` で通報、アカウント、公認設定、Ghost投稿、貸し出しサイト、チャット監査、アクティブ端末、操作履歴を確認
- 運営操作は監査履歴へ記録

### Uch

- スレッド作成・投稿・添付ファイル
- スレ主・投稿者一覧と公認/オンライン表示
- スレ主によるスレッド削除、運営による全スレッド削除
- 時報bot、キーワードbot、定型bot、Gemini AI bot
- AI botは `@bot名 質問` で呼び出し
- 投稿後のAI bot・公式bot応答はNetlify Background Functionで実行し、投稿者が画面を閉じても結果を保存。画面は定期更新で返信を取得
- 運営設定の固定プロンプト、Geminiへの返信会話、公開Uch/Ghost情報の根拠付き横断参照
- 添付の画像・音声・動画・HTMLを投稿内でプレビュー（HTMLはsandbox iframeで実行）
- スレッド・投稿の通報
- 全員オフライン中に到来した時報を記録し、誰かが復帰した際に予定時刻順で補填送信

### ぽけっと

- 個人チャット・グループチャット、ニックネーム、ロール管理
- 主・副官・カスタムロール・運営による管理操作
- 通常ユーザーから隠した削除済みメッセージの監査保持
- 運営だけが利用できるチャット監査画面
- 公認/オンライン表示とメッセージ通報
- 部屋bot・公式botの返信はBackground Functionで処理し、送信後に画面を閉じても保存される


### Custom 3Dワールド
- Three.jsによる3Dプレビューとプレイルーム
- アセットをキャンバスへドラッグ＆ドロップし、フォルダー型オブジェクト一覧から選んで個別編集
- 編集時は2本指スライドで視点移動、ピンチでズーム、2本指回転で視点回転。配置物はドラッグで移動
- ブロック、丸、柱、木、足場の色・座標・倍率と開始時/プレイヤー接近時スクリプトを編集
- Studio風の色分けプログラムブロック: 滑らかな移動・回転・ジャンプ・待機・くり返し・接近判定・ふきだし・変数
- プレイ時はThree.jsの3Dアバター、左下の仮想スティック、WASD/矢印キー、ジャンプに対応。重力で落下し、足場・ブロック上に着地
- キャラクター追従カメラは1本指スワイプ/マウスで回転、2本指/ホイールでズーム
- プロジェクトを公開ワールドとして作成し、参加者間で位置とチャットを同期
- 作成者はワールド一覧から自分のルームを削除可能
- 通話用のP2P接続IDはアカウントからサーバー側で決定的に生成し、通話レコードへ固定保存（音声・映像自体はWebRTCで端末間接続）

### Ghost

- X風のタイムライン操作感
- テキスト、画像、作品、動画、短尺動画の投稿種別
- 複数メディア、ハッシュタグ、検索
- プロフィール・アカウント一覧、フォロー、複数リストへの保存、いいね、コメント。メインフィードで保存先を選択でき、リスト作成・削除、リスト内だけ／全リストからの保存解除に対応。ブックマーク内は本文・タイトル・投稿者・タグ・投稿種別で絞り込み
- 登録時に生年月日を申告し、日本時間の誕生日ごとに年齢を自動更新。生年月日未設定の既存アカウントは利用前に初回入力が必要
- 年齢確認画面への自動遷移は有効なログインセッションがあり、サーバー上の生年月日データが未登録の場合だけ行う。未ログイン閲覧者には表示しない
- 申告生年月日は運営・副運営専用の画面から閲覧でき、一覧を開いた操作を監査記録。自己申告だけで本人確認が完了したものとは扱わない
- 未監査投稿は13歳以上のみ表示。Gemini監査で「淫夢系」「性的」「その他の年齢不適切」を区別し、10〜12歳は淫夢系（性的でないものに限る）のみ、10歳未満はどちらも表示しない
- 投稿・コメントは作成時点で監査待ちになり、過去の監査から作る語句・画像SHA-256シグネチャ最大50件で早期検出。シグネチャ一致投稿はAI再確認まで13歳未満に表示しない
- 月1回のGemini監査は15分ごとに小分けで処理。対応できない大きな画像・動画は要確認として13歳未満には表示せず、運営の「Ghost年齢監査」画面から目視確定可能
- ライブ配信: Ghost投稿画面から配信を開始し、WebRTC映像とリアルタイムチャットを提供。終了時にチャット履歴を動画アーカイブの通常コメント欄へ移行
- 投稿・コメントの通報、投稿者または運営による削除
- 淫夢・性的な投稿自体は一律禁止せず年齢別に表示制御。悪口・誹謗中傷は禁止（個人チャット内などで双方がネタとして了解している場合を除く）
- YouTube、Pixiv、TikTok、Instagramの利用感を参考にした複合メディア投稿体験
- コメント欄の開閉状態と入力途中の下書きを自動更新後も保持

Ghostライブは現状、ブラウザー間のP2P（STUNシグナリング）方式です。同時視聴は最大12人に制限しており、配信者の上り帯域を視聴者数分使用します。TURN中継サーバーやSFUは構成されていないため、NAT・ファイアウォール等のネットワーク条件によっては接続できない場合があります。配信者は配信ページを開いたままにする必要があり、ブラウザーのMediaRecorderでWebMアーカイブをチャンク保存します。

### Mail

- 受信・送信・全メールの切り替え
- 未読表示、検索、From/To・件名・本文のメールスレッド表示
- 返信・新規メール作成・通報

### 貸し出しサーバー

- 公開URLは `/site-view/{識別子}`
- HTMLミニサイトの作成・編集・削除・プレビュー
- サイトごとに分離したNetlify Blobsデータ領域
- JSON/テキストデータの保存・取得・一覧・削除
- データは1件512KB、サイト合計5MB、最大200件
- 公開データは次の形式で読み取り可能:

```text
/.netlify/functions/lending-data?slug=識別子&key=キー&public=1
```

## AI botの設定

Netlifyの環境変数へ次の名前でGemini APIキーを登録してください。

```text
GEMINI_API_KEY=新しいAPIキー
```

キーはブラウザ、HTML、JavaScript、ZIP、Gitリポジトリへ直書きせず、サーバー側Functionだけから使用します。今回の作業中にチャットへ貼り付けられたAPIキーは露出済みとして扱い、Google AI StudioまたはGoogle Cloud側で無効化・再発行してください。AI botの入力にはパスワード、認証トークン、個人情報、秘密情報を含めないでください。

Uch/Pocket/Ghostの投稿と、Webhook経由のPocket/Mail投稿に反応するGemini AI bot・公式botは、元の投稿を保存した後にNetlify Background Functionへキューイングします。呼び出し側は受理後すぐ応答し、返信はBlobsへ保存されるため、投稿者がブラウザーを閉じても処理が続きます。Netlify Background Functionsの実行上限は最大15分です。時報など既存の定期botはScheduled Functionとして引き続き実行されます。ジョブは最大24時間で期限切れになり、失敗ジョブは時間別クリーンアップで回収します。キューは短命の内部データのため、運営バックアップ/復元には含めません。

運営画面の「Geminiの固定プロンプト・権限」から固定指示（例: 運営Uch IDの対応表）、ユーザーがGeminiへ返信できるか、Geminiの返信許可、および他の閲覧可能なUchスレッド・公開Ghost投稿/コメントの検索を設定できます。Geminiの横断参照は公開/URL公開スレッド、呼び出しユーザー自身のスレッド、承認済みスレッドに限定します。パスワード保護・他人の非公開/承認制スレッド、Mail、Pocketの個人チャット、アカウントのログイン用メールアドレスや認証情報は横断参照しません。投稿内で本人が公開共有した連絡先は、その投稿を参照できる範囲で回答の根拠になり得ます。返信には参照投稿へのリンクが付きます。

UchとPocketのメッセージ添付、およびPocketのノート・アルバム画像は1.5MBずつチャンク化し、Netlify Blobsへ個別保存して参照IDだけを投稿データに記録します。アプリ独自の1ファイル合計サイズ上限は設けていません。添付を開くとUch/Pocketで画像・音声・動画・HTMLをプレビューでき、HTMLは隔離iframe上で実行します。実用上の上限はNetlify側のストレージ容量・実行時間・アカウント制限、ネットワーク、およびプレビュー時の端末メモリに依存します。

## バックアップ形式
運営画面のバックアップは、`backup/manifest.json` と `blob/<ストア名>/part-xxxxxx.json` を含むZIP形式です。各partにはストアのキーと値がまとまって保存されるため、Netlify Blobsのストア構造を確認しやすく、JSON単体より圧縮・保存・移送に向きます。読み込みはZIPを展開して既存の分割復元処理へ渡し、旧JSONバックアップも互換読み込みできます。

## デプロイ

1. このプロジェクトをNetlifyへ新規サイトとして登録します。
2. `netlify.toml` の `publish = "public"` と `functions = "netlify/functions"` が適用されていることを確認します。
3. Netlify Blobsを利用できるよう、サイトのデプロイ環境でBlobsが有効になっていることを確認します。
4. `GEMINI_API_KEY` をNetlifyの環境変数へ登録します。ローカルでの検証時は、実キーではなくダミー値を使用してください。
5. `scheduled-tokibou` は毎分、`scheduled-ghost-moderation` は15分ごとのスケジュールです。Netlify側のScheduled Functionとして両方が認識されていることを確認してください。

## セキュリティ上の注意

パスワードは復元・表示できない設計です。ログインできない場合は、本人確認後の運営リセットを利用してください。生年月日は本人申告の個人情報であり、運営バックアップにも含まれるため、バックアップファイルを暗号化された安全な場所で保管してください。個人チャット監査は運営権限をサーバー側で検証した管理APIからのみ行い、操作履歴を保存します。公開HTMLはサンドボックス化されたiframeで配信されますが、公開サイトへ秘密情報を埋め込まないでください。

人間判定は簡易チェックボックスです。公開運用ではhCaptcha、Cloudflare Turnstile等の実サービスへ差し替えてください。Netlify CLIを使ったビルドはサイトIDのリンクが必要なため、この配布物ではNode構文検査とインメモリスモークテストで主要処理を検証しています。

## Ghostの運営タグ

運営ダッシュボードの「Ghostワンタップ用タグ設定」から、タグ名、説明文、表示順、有効/無効を設定できます。設定変更は運営アカウントだけが実行でき、操作履歴にも記録されます。Ghost投稿画面では有効なタグがワンタップボタンとして表示され、ボタンの説明文はツールチップとして確認できます。

投稿フォームのタグ欄はテキストエリアになっており、1行1タグで入力できます。空白区切りとカンマ区切りも引き続き利用でき、先頭の `#` は自動的に取り除かれます。日本語、英数字、アンダースコア、ハイフンを使用できます。

管理タグAPIの公開一覧は `/.netlify/functions/ghost?tags=1` で取得でき、運営トークン付きの場合は無効タグも確認できます。投稿作成APIでは通常の `tags` に加えて、ワンタップ選択分を `quickTags` として送信できます。

## 参照CURLを応用したGemini連携

指定された参照テキストにある `gemini-flash-latest:generateContent`、`Content-Type: application/json`、`X-goog-api-key`、`contents[].parts[].text` の構成をUchのAI botへ反映しています。加えて、botごとの指示文、生成設定、20秒タイムアウト、APIエラー表示を実装しています。

参照テキストに含まれていたAPIキーは漏洩防止のため取り込んでいません。Google APIキーをHTMLやJavaScript、ZIPへ埋め込むと、利用者や第三者がキーを取得して不正利用できるためです。Netlifyの環境変数 `GEMINI_API_KEY` に登録した値だけをサーバー側Functionが読み取る構成にしてください。

## Geminiキーの自動設定

キー入力の手間を減らすため、`scripts/configure-gemini-env.sh` を追加しています。このスクリプトはキーをファイルへ書き込まず、非表示入力で受け取った値をNetlify CLIへ直接渡してProduction環境の `GEMINI_API_KEY` に登録します。

プロジェクトのルートで次を実行してください。Netlify CLIのログイン済み状態と、対象サイトへのリンクが必要です。サイトをリンクしていない場合は、実行前に `NETLIFY_SITE_ID` を一時的に設定できます。

```bash
./scripts/configure-gemini-env.sh
# または
NETLIFY_SITE_ID=あなたのサイトID ./scripts/configure-gemini-env.sh
```

入力値は画面に表示されず、スクリプト終了後にも保存されません。登録後はNetlifyで再デプロイしてください。参照テキストに含まれていた既存キーは使用せず、必ずGoogle側で再発行したキーを入力してください。

## バックアップ後の保護ロック

運営ダッシュボードの「全データをバックアップしてロック」を実行すると、ストアのキー索引を作成してデータを小分けに取得し、ダウンロード準備後にサイトの保護ロックを有効化します。エクスポート中の一時索引は実データと分離して保存し、完了時に削除します。一般公開ページには保護ロック表示を出し、貸し出しサイトの公開ビューはサーバー側でHTTP 503にします。ロック解除は運営アカウントで `/admin` を開き、「サイトロックを解除」から実行できます。

「運営」アカウントは主運営と同等の管理権限を持ち、バックアップ操作および副運営の任命・解除を行えます。副運営は運営機能を利用できますが、運営ロールの任命・解除はできません。管理画面の更新時にサーバー上の最新ロールを再取得するため、権限付与後の再ログインは不要です。

バックアップにはアカウント、パスワードハッシュ・ソルト、ログインセッション、APIキー等の秘密情報も含まれます。平文パスワードは保存されていないため含まれません。バックアップファイルは運営だけがアクセスできる安全な場所に保管してください。復元すると現在の保存データが置き換わります。

## P2P通話・ビデオ・画面共有

Pocketのルーム参加者から音声通話、ビデオ通話、画面共有通話を開始できます。音声・映像データはWebRTCで端末間接続し、サーバーは通話内容を中継せず、接続確立用のシグナリング情報と通話履歴のみを保存します。オンラインの相手には着信通知を表示し、オフラインの相手には未通話履歴として保存します。

マイク、カメラ、画面共有を使う場合は、ブラウザの権限許可が必要です。WebRTCは接続確立のためSTUNを利用し、環境によっては直接接続できずTURN中継サーバーが必要になる場合があります。TURNを使用する場合は、認証付きの外部TURNサービスを別途設定してください。

## Manus運営コンソール

運営ダッシュボードには、Manusから渡されたアプリ専用コマンドを貼り付けて実行できるコンソールがあります。既存のタグ管理UIや各管理UIは残っており、コマンドからも同じ管理データを操作できます。

例:

```text
help
status
env status
ghost tags
ghost tag add お知らせ | 重要なお知らせ | 1 | on
ghost tag edit タグID | 更新後のタグ | 説明文 | 2 | on
ghost tag delete タグID
official on user@example.com
password reset user@example.com
file list
file read settings.json
file write settings.json {"theme":"dark"}
file delete settings.json
audit archive audit-id
```

`file` コマンドはアプリ専用の管理Blob領域だけを対象にし、OSファイルや任意のshellは実行しません。管理ログは完全削除せずアーカイブ扱いにします。破壊的な操作は画面上で確認を求め、すべてのコマンド操作を監査履歴へ記録します。

## Blob容量ローテーションとPocket拡張

各論理ストアは、`netrify-storage-routing` に保存されたルーティング情報をもとに複数の論理シャードへ分割されます。現在のシャードが設定上限に近づいた場合、または書き込みに失敗した場合は、`<ストア名>::shard:N` を次の保存先として作成し、続きのデータを書き込みます。既存データは全シャードを横断して読み取り、重複キーは新しいシャードを優先します。

Pocketでは、主または運営によるルーム名編集、主・副官・運営またはbot管理権限ロールによるbot追加・削除が利用できます。botはルーム内で `@bot名` とメンションされた場合に定型返信します。ルームを開いた際は最新メッセージ位置を初期表示し、利用者が上方向へ履歴を閲覧している間は自動更新で下へ強制移動しません。

## ツールセンター（`/Tools`）

既存のアプリ・サーバー・ファイルを保持したまま、ツールセンターと `netlify/functions/tools.js` を追加しました。匿名共有以外のツール利用はログインが必要です。

- 匿名メッセージ箱: アカウントごとに1つの受信ページを作成。送り手はログイン不要で、所有者だけが受信箱を閲覧・削除できます。簡易レート制限と文字数制限あり
- AIお悩み相談: 穏やか、ツンデレ、関西弁、哲学者の話し方を選択。会話は保存しません。Gemini APIキーがNetlify環境変数に必要
- レコメンドAI・献立提案: 入力した好きな作品・食材だけをAIへ送信。好みや冷蔵庫の一覧はブラウザのlocalStorageに保存
- Wiki: 公開ページの一覧・閲覧・作成。編集・削除は作成者だけ
- 一時チャット: URLを知っている人がアカウントなしで参加。6時間で失効し、毎時実行のScheduled Functionが期限切れデータを削除
- 共有ロッカー: テキストまたは約3.5MBまでのファイルを、推測困難なURLで1〜24時間共有。既定6時間。URLを知る人は削除も可能。毎時のクリーンアップにより期限後に削除
- 一括画像変換、QRコード、Markdown、画像色抽出、OCR、ポモドーロ、クリップボード、本棚、部屋配置、訪問地とお気に入りスポット地図、文字数分析、リンク検査、JSON/YAML、冷蔵庫、画面分割
- 端末固有の作品リスト・クリップ・本棚・部屋・訪問地・スポット・冷蔵庫データはlocalStorageに保存し、サーバーへ同期しません。画像変換・色抽出・OCRは画像自体をサーバーに送信しません
- Leaflet/OpenStreetMap、Tesseract.js、Marked/DOMPurify、js-yaml、QRCode.jsをCDNから読み込みます。ネットワークや埋め込み制限により外部ページ・ライブラリが利用できない場合があります
- リンク検査は公開HTTP(S)サイトのトップページから最大25リンクを確認します。ローカル/プライベートネットワーク宛てを拒否し、リダイレクト先は自動追跡しません
- Pocketメッセージの一部を選択すると「選択部分をコピー」ボタンが表示されます。本文全体のコピーも従来どおり可能

集中タイマーの環境音はブラウザのAudioContextで合成する簡易ノイズで、録音済みの雨音ではありません。通知音の再生はブラウザの音声設定・ユーザー操作に従います。

### Uchスレタグ

スレッド作成時に最大8個（各24文字まで）のタグを設定できます。一覧はキーワード検索に対応し、複数タグを「どれかに一致」または「選択タグすべてに一致」で絞り込めます。本文抜粋も検索対象です。既存スレッドはタグなしとして表示され、データ移行は不要です。

### 追加ストアとバックアップ

`TOOL_DATA`、`ANON_BOXES`、`TEMP_ROOMS`、`TEMP_SHARES`、`WIKI` を既存のストレージ定義に追加しました。管理バックアップが `STORE_NAMES` を列挙する既存実装であれば、これらもバックアップ対象に含まれます。既存の全ストア・サーバー設定・ファイルは今回の変更で削除していません。期限付き共有のクリーンアップは毎時実行されます（Netlify Scheduled Functionsが有効であることが必要です）。

ヒーロー画像: Unsplashの「Cozy Desk Pictures | Download Free Images on Unsplash」検索結果から取得し、`public/images/toolbox-workspace.jpg` に最適化して同梱しています。

## 運営ログインメールの変更

管理画面の「運営ログインメール変更」は主運営アカウントのみ利用できます。現在のパスワードと確認チェックが必要です。実行時には、アカウントストアを新アドレスへ移し、各ストア内の完全一致するメールアドレス参照（所有者・投稿者・参加者など）を移行します。旧アドレスは `loginAliases` として保持されるため、旧アドレスでもログインできます。既存の主運営セッションは全て失効し、変更操作は `ADMIN_AUDIT` に旧・新アドレス、移行時刻、全端末失効の記録を残します。完了後は新アドレスで再ログインしてください。
